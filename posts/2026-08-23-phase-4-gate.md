# Phase 4 gate: the loop safety layer passed

*2026-08-23 · ai-portfolio-sentinel · learning lane. Status: in
development toward production-ready. No production claim is made here.*

Phase 4 is the part of this system that supervises something bigger
than a single run: one bounded loop spanning up to ten complete runs,
with durable state of its own. It adds a cost breaker, a
consecutive-failure breaker, a crash-safe run identity that is written
down before any work starts, and a published log derived from that
durable state. Its technical gate has now run, and it passed.

The order matters more than the result. The gate was frozen first, in a
separate session, with a closed set of thirty-three predicates written
before the run they would judge. Then the gate executed once, from that
exact frozen source, and was not run again — not for confirmation, not
after looking at the output. Nothing in the runner was adjusted to make
it pass. That sequencing is the whole discipline: a gate you can tune
after seeing its verdict is not a gate.

All 33 predicates passed. The normal leg drove ten iterations through
the real machinery and proved contiguous indexes, unique run
identities, terminal runs and tasks, one cost row per run, and
continuity across iterations. The cost leg walked the boundary
deliberately: at 749,999 micro-euros against a 750,000 ceiling the loop
continues, but the next iteration's allowance drops to exactly 1 and is
never quietly restored; at exactly the ceiling the next iteration is
refused and no further run starts; above it the overshoot is recorded
in full and never trimmed to look tidy. Reaching the iteration cap
exactly at the ceiling is normal completion; reaching it above the
ceiling is a tripped breaker. The failure leg proved the trip at
exactly three consecutive failures, the fourth iteration never
starting, a fail-fail-success-fail-fail sequence correctly ending at a
streak of two, and the streak outranking normal completion at the
boundary. The crash leg killed the process after a run was terminal but
before the loop had recorded it, then proved the restart adopts that
run rather than repeating it.

Zero model calls. Zero provider spend. This gate is deliberately
model-free, which means it says nothing about how a real model behaves
inside the loop, and nothing about any provider's reliability. It
proves the safety layer mechanically, which is exactly what it was
scoped to prove.

One more distinction worth keeping straight: the published iteration
log is derived evidence, not the system's state. The durable ledger and
the durable cost rows are authoritative, and the gate checks the log
back against them rather than trusting it.

The honest limitation: this does not close Phase 4. A technical pass
alone never did. The operational documents mapped to this phase — the
test matrix, the incident-response guide, and draft monitoring and
runbook documents — are landing alongside this post, and formally
closing the phase is a separate recorded step after that. Phase 5 is
still its own thing: moving the schedule to hosted CI, the official
model gate, real scheduled operating history, and the final operations
documents.
