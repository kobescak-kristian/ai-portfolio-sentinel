# Phase 0 gate: enforcement before features

*2026-08-03 — ai-portfolio-sentinel, a learning-lane experiment.
Status: in development toward production-ready. No production claim
is made here.*

Phase 0 of this project shipped no monitoring capability at all —
deliberately. What it shipped is the machinery that makes every later
claim checkable: hooks that guard, telemetry designed before the
thing it measures exists, and CI from the first push.

**What was built.** A frozen cost-telemetry contract (a CostRow with
exactly eight fields; currency as integer micro-euros, never floats),
an append-only JSONL ledger with a byte-exact serialization rule, a
dry run that proves a row can be written and read back without
leaving a single generated file in the repository, and 36 tests
covering the contract's edges: naive datetimes rejected, non-UTC
offsets rejected, machine-local absolute paths rejected in free-text
fields, environment values proven absent from serialized output. CI
runs the whole suite plus the repository's artifact validator on
every push, on one declared runtime (ubuntu-latest, Python 3.12) —
declaring one tested platform honestly rather than advertising a
matrix nobody verified. Alongside the code: a condensed operating
spec, a claims-ladder amendment, and a decision record opening a
production-readiness program with named closure artifacts mapped to
later phases.

**The gate story, including the part where it said no.** Before any
push, the repository publish gate runs: secrets scan across history,
private-content scan, structure checks, workflow audit. It caught two
real things this time. First, a pre-existing line in the public STATE
file carried a path fragment pointing into a private repository —
committed weeks ago, sitting in public the whole time. It is gone
now, replaced by a reference by date. Second, the gate refused to
pass at all on its first run: the scan requires a coverage canary — a
deliberately planted fake finding that the scanner must detect to
prove the scan itself still reaches everything — and this repository
did not have one. The verification system halted on the absence of
proof that the verification system works. That is not an
inconvenience; that is the design working. The canary was added as
its own commit, the gate re-ran from the new state, and only then did
anything reach the public branch.

**Why a leak drill, too.** The pre-push hook's secret scan was tested
against a seeded fake credential in a disposable clone — the hook
blocked the push, the clone was destroyed, and the real repository
was proven untouched. A guard that has never fired is a hope, not a
control.

**What Phase 1 is.** The eval gate gets built before the system it
gates: synthetic fixture repositories with injected defects across
five check classes, an answer key authored under a blind-labeling
protocol, and thresholds frozen with their integer meaning stated —
how many misses each ratio actually allows at the final fixture
counts. No agent code exists until that gate is frozen. The point of
this lane is the discipline, and the discipline starts with the
measuring stick.
